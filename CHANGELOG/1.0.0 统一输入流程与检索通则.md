# 1.0.0 统一输入流程与检索通则

> 2026-08-26

自 0.2.0 起累积了律所（合伙人制中小所、红圈所）、道路救援、民宿托管等多轮实战。暴露的共性问题是：输入形态千奇百怪，二分的模式路由套不上；素材"不少但成色弱"无规则可依；检索规则散在三处，素材充足时反而读不到。本版把流程收敛成一条，把检索规则收进一份独立文件。

## 摘要

1. 优化: 不再按"有没有访谈"分两种模式走两条流程——给一句话、给公司名、给整份访谈记录都走同一套骨架，报告深度改为逐节逐句由证据决定
2. 新增: 有素材时先做「素材成色三问」——谁在说话、站什么视角、对着骨架哪几章撑不住，评完挑明给用户再开工
3. 优化: 检索规则从三处散落合并成一份 `references/research.md`，有无访谈都读它；原 `desk-research.md` 只留无访谈时的留白与提纲
4. 新增: 第一章可按需插入「细分行业」节，用同一大行业下几类角色的横向对比反衬主角的位置
5. 优化: 判断一句话能不能写，判据从"证据是不是访谈来的"改成"证据够不够具体可溯源"——司法判决、招股书、深度报道里的从业者原话，查到了按一手素材用
6. 新增: 正文黑话悬停即显解释，不用跳到附录再跳回来
7. 优化: 访谈提纲的问题按痛点优先级排，先问最贵的那几条，不按章节顺序排
8. 优化: 第三章从「需求分析」改名「业务流程」
9. 修复: 机检补两类硬伤——引用块用 `</p>` 收尾会把后面整章吞进引用样式、SVG 画布下方留出大片空白
10. 优化: 自检清单不再复述规则原文，只留可勾选的判据；skill 描述从 360 字压到 130 字
11. 优化: 交付通道只剩 HTML 与 PDF，飞书文档同步整条删除
12. 优化: 终稿收口收敛成一条命令；数字里"哪些是真的、哪些是推的、哪些是编来举例的"拆成三层写明，不再混为一谈

## 详情

### 1. 优化: 所有输入走同一套流程

原先按输入形态分流：有访谈走模式 A，只给行业名或零散笔记走模式 B，两套流程并行维护。实战中出现了两类都套不上的输入（如"系统反向分析素材"），临场发明过"弱一档"的第三种走法。

**改前**：第 0 步先做 A/B 分流表，两种模式各有一套深度规则，"访谈才拿得到的内容不许编"是模式 B 专属红线。

**改后**：分流表删除，"第 0 步"整节取消。深度原则压成工作流程开场一句：

> 所有输入同一套骨架与流程；深度由证据决定，逐节、逐句生效——判据是"有没有具体可溯源的证据"，不是"证据是不是访谈"。

"只有访谈才拿得到的内容宁可留白也不推演"从模式 B 红线升级为全局红线。公司名前置检查与素材单薄挑明并入流程第 0 条。全文（含 description、自检清单）清除"模式 A/B"字样。

### 2. 新增: 素材成色三问

兜住"素材不少但视角偏"的情形——曾有一轮实战中拿到的所谓访谈素材实为销售通话，讲的是卖东西而非行业运转，按字数算素材充足，按可用性算几乎为零。

有素材时必做，三问：

1. **谁在说话**——从业者本人＞服务商/销售转述＞二手整理的纪要；
2. **站什么视角**——讲行业运转，还是卖东西/答客户问（后者的行业信息是顺带的、碎的）；
3. **对着报告骨架扫覆盖**——逐章标"撑得住/撑不住"，撑不住的章节提前按留白规则处理。

评完把结论挑明给用户，再决定补素材还是接受留白。

### 3. 优化: 检索规则合并为 research.md

检索规则原先散在三处：SKILL.md 工作流程第 3 步的 8 条子项、`desk-research.md` 的扩口径与渠道六类、`framework.md` 的取数细则。更麻烦的是 `desk-research.md` 这个文件名与内容不符——它自己写着"渠道六类有无访谈通用"，但 SKILL.md 里指向它的两个 pointer 都写着"素材不足时"，导致素材充足的那次运行读不到那张渠道表，而第 3 步的"渠道类型 ≥ 3 类"判据恰恰依赖它。

**改前**：

```
SKILL.md 第 3 步
  - 必查三类 / 证据地图 / 来源分级 / 不必查 / 换三招 / 查到哪停 / 硬数字核原文（8 条子项）
desk-research.md（pointer 写作"素材不足时"）
  - 检索：先扩口径 + 渠道六类表 + 控 token 漏斗
  - 逐节留白表 + 访谈提纲
```

**改后**：

```
SKILL.md 第 3 步
  - 保留判断原则：机制听素材、数字听公开权威源、叙事权跟证据成色走
  - 其余换成一个必读 pointer（4 条子项）
references/research.md（新增，pointer 写作"有无访谈都适用"）
  - 必查三类 / 扩口径与渠道六类 / 证据地图与 token 漏斗 / 来源三级 / 查到哪停 / 硬数字核原文
desk-research.md（pointer 写作"无一手访谈时"）
  - 逐节留白表 + 访谈提纲 + 铁律加强
```

### 4. 新增: 第一章按需的「细分行业」节

仅当主角是"大行业下的一类角色"时插入；主角本身就是整个行业、没有并列细分时跳过。目的是**用同一大行业下几类角色的横向对比反衬主角的位置和特性**，不是平均介绍每一类。

写法：选两条最能拉开差距的轴做二维定位图（主角 accent 实心），图后按类逐条讲"这一类靠什么挣钱、和主角差在哪"，最后收回主角所在的那一格——它的一切经营特征都由这个位置决定。两条轴撑不起来就退成对比表转图；分类勉强、区别全是套话时，退回纯文字对比或不写。

插入本节后原「发展阶段」「业务规模」顺延为 1.3、1.4，全文小节 id 与目录一并顺延。模板加占位与目录项，`framework.md` 第一章后两节标题去掉编号（编号随本节浮动，以 SKILL.md 骨架为准），`desk-research.md` 逐节表补对应行。

### 5. 优化: 证据判据从"来源类型"改为"证据质量"

**改前**：行业内部机制（利润账、灰色链路、黑话、一线痛点）写死为"只有访谈才拿得到"。

**改后**：

> 行业内部机制通常只有访谈才拿得到，但高质量公开证据（司法判决、监管处罚、招股书、深度报道里的从业者原话）查到了同样能撑住，按一手素材对待、标明来源。

`desk-research.md` 逐节表的"查不到——留白"明确以**做完两层扩口径后仍查不到**为前提，泛泛的二手综述文章不算一线证据。

配套：叙事权跟证据成色走——谁更接近一线谁当叙事源，成色三问评下来弱的部分，查到更接近一线的公开证据就用它当叙事。数字/年份/名单里素材只是"去哪查"的路标，按三级源对待。

### 6. 新增: 术语悬停卡

模板内置纯内联 CSS + JS：正文 `a.term` 悬停或点按直接浮出附录对应词条的解释（取 `#term-*` 的 dt/dd 渲染浮层），点击不再跳转附录。术语表保留供整体回查；正文里没有对应词条的黑话仍用 `span.term` 不加链接。

### 7. 优化: 访谈提纲按痛点优先级排序

**改前**：排序判据是"填上之后报告会活过来"。

**改后**：每个留白先挂上它服务的痛点（3.2 里查得到的痛点，或 3.3 的 P0/P1 死结），再按 P0 → P1 → 背景铺垫排。痛点还看不清时才回退到旧判据当代理。

动因：提纲的排序要和报告 3.3 的建议优先级同一套口径——问的顺序即价值的顺序，受访者时间有限时先问的一定是最贵的那几条。

### 8. 优化: 第三章更名

「需求分析」→「业务流程」。模板、`framework.md`、`SKILL.md`、`README.md` 同步。

### 9. 修复: 机检补两类 FAIL

- **div 闭合不平衡**：`callout` / `warnbox` 误用 `</p>` 收尾，会把后续整章吞进引用样式，浏览器不报错、肉眼一眼能看出，机检原先漏掉。
- **SVG 画布下方大片留白**：viewBox 高度远大于实际内容最低点，图下方空出一片。

配套一致性清理：`framework.md` 图号硬编码改图名引用（呼应"图号不写死"）、自检清单改节名引用（不受编号浮动影响）、"证据地图"术语归第 3 步专用、`framework.md` 页脚接上无访谈场景。

### 10. 优化: 自检清单去重与 description 压缩

**自检清单**：11 条重新表述成断言句，去掉已在铁律或 `framework.md` 里写过的解释，只留可勾选的判据加章节 pointer。规则一条未删，改的是"同一条规则不在两处各写一遍"。

改前 → 改后示例：

| 改前 | 改后 |
|---|---|
| 2.2 的产品全景图做到细分 + 对比（见 framework §2.2），没重讲业务流程、没拿"客户图什么好处"当产品构成；图后文字把概念讲活，不是复述图 | 2.2 产品全景图做到细分 + 对比，图后文字把概念讲活而非复述图（framework §2.2） |
| **数字与事实可溯源**：每个数字答得出"哪来的"、口径齐全、页脚可查；客观事实都查过（不只发展阶段与业务规模两节）；全行业断言已验证或降级"受访者认为" | **每个数字答得出"哪来的"**：口径齐全、页脚可查；客观事实不只查了发展阶段与业务规模两节；全行业断言已验证或已降级 |

**description**：从 360 字压到 130 字。原文做了四件事——讲产出形态、讲两种输入、列六种触发说法、列排除项；其中"出一份行业分析报告／梳理／普及／讲给小白听／分析／研究／摸个底"是同一个分支写了六遍。改后保留三个真分支（有访谈素材、只给行业名、只给公司名）与排除项，砍掉正文已承载的产出形态和同义触发词。

**SKILL.md 整体**：16.8k → 13.6k 字符，`desk-research.md` 8.5k → 6.7k，新增 `research.md` 4.7k（仅在第 3 步触发时加载）。常驻与每次必读部分净降约 5k 字符。

### 11. 优化: 删除飞书文档交付通道

**改前**：交付形态三选——HTML、PDF、飞书文档；飞书通道含 HTML→飞书 XML 转换、SVG→PNG 导出、占位符搬运，配 `references/lark-sync.md` 与 `scripts/export_png.py`。

**改后**：只保留 HTML 与 PDF。第 7 步交付只问一句"要不要导 PDF"。`references/lark-sync.md`、`scripts/export_png.py` 及相关插图尺寸规则一并删除。飞书作为**输入**（读飞书文档里的访谈素材）不受影响。

### 12. 优化: 终稿收口与数字纪律

**终稿收口收敛成一条命令**：`python3 scripts/finalize.py <报告.html>` 一个入口，由它重导 `figures/` 并调用内容检查与图形检查两个专项检查器，工作流里不再分别手工执行。改过任何一张内嵌 SVG 都必须重跑，否则独立 SVG 停在旧版。

**数字纪律拆成三层**：

> 事实必须真实，推断必须有据，示例可以假设——三者绝不混淆。

示例（如资金流转图里的"1 万元订单账"）是把生意讲活的合法手段，不要为客观而删；但须算术自洽、紧邻标注"示意，非企业真实数据、非行业统计"，只用于解释机制，不得用来证明行业价格、利润率或规模。

**3.3 定性为建议优先级**：P0–P3 开头须言明这是基于访谈与公开资料的**建议排序**，不是受访者确认过的顺序；每条要能回指 3.2 的痛点或素材依据，受访者没说过的目标不许写成他的原话诉求。

**自检清单加终极验收题**：不懂该行业的产品经理读完，能否三句话复述"主角怎么赚钱、卡在哪里、最需要什么"——机检 FAIL 0 不等于报告合格，这一条才是。
